# DPS XML Recovery

Портативная Windows-программа для восстановления собственного архива XML-документов из приватного API Электронного кабинета ГНС Украины.

Программа получает перечень отчётных документов за выбранный период, скачивает основные и связанные XML, проверяет их структуру и SHA-256, поддерживает продолжение после остановки и формирует финальный аудит. Она не импортирует документы в M.E.Doc и не изменяет данные в ГНС.

> Используйте программу только для данных, к которым у вас есть законное право доступа. Это независимый проект, не официальный продукт ГНС, АО «ИИТ» или M.E.Doc.

## Возможности

- помесячный inventory с поддержкой пагинации API;
- загрузка основных и связанных XML;
- атомарная запись через временные `.part`;
- проверка XML и SHA-256;
- persistent state и продолжение после остановки;
- финальный аудит `inventory → XML → manifest`;
- режимы полного восстановления, inventory-only и audit-only;
- безопасный диагностический отчёт без пароля, Authorization и содержимого XML;
- пути с кириллицей, пробелами и Unicode.

## Системные требования

- Windows 10 x64 — проверена;
- Windows 11 — пока не проверена;
- Windows Server 2016 — пока не проверена;
- официальный установленный и настроенный комплекс **«ІІТ Користувач ЦСК-1»** с совместимой 32-битной `EUSignCP.dll`;
- действующий JKS-файл КЭП и пароль;
- доступ к приватному API Электронного кабинета ГНС;
- свободное место для XML-архива.

`DPSXmlRecovery.exe` — 32-битное портативное приложение. Python и .NET Runtime устанавливать не требуется. Самому приложению права администратора не нужны. EXE пока не подписан, поэтому Windows может показать предупреждение SmartScreen.

## Установка комплекса ИИТ

1. Скачайте Windows-пакет только с [официального сайта АО «ИИТ»](https://eu.iit.com.ua/).
2. Установите и настройте комплекс по инструкции производителя. Установщику ИИТ могут потребоваться права администратора.
3. Убедитесь, что доступна 32-битная `EUSignCP.dll`, а сертификаты и доверенные центры настроены средствами ИИТ.
4. Не копируйте DLL в каталог DPS XML Recovery: программа использует официальную локальную установку.

Формат авторизации описан в [документации приватного API Электронного кабинета](https://cabinet.tax.gov.ua/help/en/api-registers-int.html).

## Пошаговый запуск

1. Скачайте ZIP из GitHub Releases и при необходимости сверьте SHA-256.
2. Полностью распакуйте ZIP в обычный пользовательский каталог. Не запускайте EXE прямо из архива.
3. Запустите `DPSXmlRecovery.exe`.
4. Нажмите **«Проверить ІІТ»** и продолжайте только после успешной проверки.
5. Введите свой ЕГРПОУ или РНОКПП.
6. Выберите JKS, обновите список alias и выберите нужный alias.
7. Введите пароль КЭП. Он используется только текущим worker-процессом и не сохраняется.
8. Укажите начальный и конечный годы и отдельный каталог нового архива.
9. Выберите режим и нажмите **«Начать восстановление»**.
10. Дождитесь финального аудита. Полное восстановление успешно только при финальном **PASS**.

## Остановка и resume

Кнопка **«Остановить»** запрашивает кооперативную остановку на ближайшей безопасной контрольной точке. Она может занять некоторое время.

Для продолжения снова откройте приложение, выберите тот же каталог, период и режим, повторно введите пароль и запустите задачу. Уже проверенные объекты повторно не скачиваются. Не редактируйте `data`, manifest или state между запусками.

## Режимы

- **Полное восстановление** — проверка API, inventory, загрузка XML, manifest и финальный аудит. PASS показывается только после аудита.
- **Только inventory** — получает и проверяет перечень документов, но не скачивает XML. Успех inventory не означает PASS архива.
- **Только аудит** — локально проверяет существующий архив без JKS и сети ГНС: state, manifest, XML, SHA-256, ошибки и `.part`.

Технические режимы скрыты в дополнительных настройках и обычному пользователю не нужны.

Для контрольного CLI корнем по умолчанию является относительный каталог `recovery` в текущем рабочем каталоге. Его можно изменить параметром `--root` или переменной `DPS_XML_RECOVERY_ROOT`. Если у оператора есть отдельный неизменяемый контрольный архив, его путь можно запретить для CLI через `DPS_XML_RECOVERY_LEGACY_ROOT`; список защищённых корней GUI задаётся через `DPS_XML_RECOVERY_PROTECTED_ROOTS`, разделённый системным разделителем путей.

## Хранение и безопасность

- XML, metadata, state, manifest и audit report сохраняются в выбранном каталоге;
- настройки и безопасные operational logs — в `portable-data` рядом с EXE либо в явно выбранном доступном каталоге;
- JKS остаётся на исходном месте, а путь запоминается только с явного согласия;
- пароль КЭП передаётся локальному worker-процессу через одноразовый Windows anonymous pipe и не сохраняется;
- пароль, Authorization и содержимое XML не должны попадать в настройки, логи или диагностику;
- `EUSignCP.dll` не входит в ZIP и используется из официальной установки ИИТ;
- подписанная авторизация используется для доступа к приватному API ГНС.

Эти меры снижают риск, но не являются заявлением об абсолютной безопасности. Пользователь отвечает за защиту JKS, Windows-учётной записи, архива и резервных копий.

## Типичные ошибки

- **«ІІТ не готов»** — проверьте официальную установку, x86 DLL, цифровую подпись и настройки сертификатов. Не скачивайте DLL отдельно с неофициальных сайтов.
- **JKS или alias не читается** — проверьте файл, права доступа, alias и пароль. Программа не восстанавливает пароль и не изменяет JKS.
- **Ошибка авторизации** — проверьте срок КЭП, право подписи, системное время и настройки ИИТ. Не передавайте JKS, пароль или полный Authorization.
- **Inventory/API не завершается** — проверьте сеть и доступность Электронного кабинета, повторите позже, экспортируйте безопасную диагностику. Частичный inventory не является полным архивом.
- **Остались `.part` или аудит failed** — PASS не подтверждён. Не редактируйте `.part`; повторите запуск с тем же каталогом либо audit-only.
- **SmartScreen** — EXE не подписан. Проверяйте источник ZIP и SHA-256; при сомнениях не запускайте файл.

Перед передачей диагностики просмотрите её самостоятельно. Не публикуйте XML, JKS, пароль, Authorization, персональные данные или пользовательские пути.

## Проверенный результат

Кандидат 2.0.2 прошёл 177 автоматических тестов и package audit. Пользователь подтвердил реальное восстановление 347 XML: 135 основных, 212 связанных, 0 невалидных XML, 0 `.part`, 0 ошибок аудита и финальный PASS.

Это результат конкретного проверенного запуска, а не гарантия для любого ключа, аккаунта, сети или будущей версии API.
