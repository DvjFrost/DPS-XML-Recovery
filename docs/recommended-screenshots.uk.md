# Рекомендовані скриншоти для GitHub Release

Усі знімки робити лише з тестовими даними. Перед публікацією перевірити фон робочого столу, заголовки вікон, taskbar, історію шляхів та діагностичні файли.

1. **Головне вікно після успішного preflight ІІТ** — явно синтетичний ідентифікатор `00000000`, шлях `C:\TestData\demo-key.jks`, alias `0: TEST_KEY`, порожній пароль.
2. **Заповнені параметри перед запуском** — період 2024–2025, каталог `C:\TestData\DPS-Recovery-Demo`, режим повного відновлення.
3. **Inventory у роботі** — штучний прогрес, наприклад `12/24`; жодних document ID, форм або відповідей API.
4. **Download у роботі** — штучні лічильники без назв реальних документів.
5. **Безпечна зупинка** — статус очікування контрольної точки та подальший стан `Зупинено`.
6. **Фінальний PASS** — лише тестові підсумкові лічильники, `invalid=0`, `.part=0`, `errors=0`.
7. **Режими відновлення** — full, inventory-only та audit-only без розділу з реальними файлами.
8. **Безпечний діагностичний звіт** — синтетичний JSON із дозволеними полями; не показувати локальні шляхи користувача.

Не показувати: реальні ЄДРПОУ/РНОКПП, ПІБ, назви організацій, JKS, пароль, alias реального ключа, сертифікат, Authorization, XML, `codRegdoc`, локальні користувацькі каталоги або вміст operational logs.
