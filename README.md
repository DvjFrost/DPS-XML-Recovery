# DPS XML Recovery

Портативна Windows-програма для відновлення власного архіву XML-документів з приватного API Електронного кабінету ДПС України.

Програма отримує перелік звітних документів за вибраний період, завантажує основні та пов’язані XML, перевіряє їхню структуру і SHA-256, підтримує продовження після зупинки та формує підсумковий аудит. Вона не імпортує документи в M.E.Doc і не змінює дані в ДПС.

> Використовуйте програму лише для даних, до яких маєте законне право доступу. Це незалежний проєкт, не офіційний продукт ДПС, АТ «ІІТ» або M.E.Doc.

## Можливості

- інвентаризація документів за місяцями з урахуванням пагінації API;
- завантаження основних і пов’язаних XML;
- атомарний запис через тимчасові `.part`-файли;
- перевірка XML та розрахунок SHA-256;
- постійний локальний стан і безпечне продовження після зупинки;
- фінальний аудит `inventory → XML → manifest`;
- окремі режими inventory-only та audit-only;
- безпечний діагностичний звіт без пароля, Authorization і вмісту XML;
- Unicode-шляхи, пробіли та кирилиця в іменах каталогів.

## Системні вимоги

- Windows 10 x64 — перевірено;
- Windows 11 — ще не перевірено;
- Windows Server 2016 — ще не перевірено;
- офіційно встановлений і налаштований комплекс **«ІІТ Користувач ЦСК-1»** із сумісною 32-бітною `EUSignCP.dll`;
- чинний JKS-файл КЕП і пароль до нього;
- доступ до приватного API Електронного кабінету ДПС;
- вільне місце для архіву XML.

`DPSXmlRecovery.exe` є 32-бітним портативним застосунком. Python та окремий .NET Runtime встановлювати не потрібно. Самій програмі права адміністратора не потрібні. EXE поки не підписаний цифровим підписом, тому Windows може показати попередження SmartScreen.

## Встановлення комплексу ІІТ

1. Завантажте інсталяційний пакет для Windows лише з [офіційної сторінки АТ «ІІТ»](https://eu.iit.com.ua/).
2. Встановіть і налаштуйте комплекс за настановою виробника. Інсталятор ІІТ може мати власні вимоги до прав адміністратора.
3. Переконайтеся, що встановлена 32-бітна бібліотека `EUSignCP.dll` і налаштовані сертифікати та довірені центри сертифікації.
4. Не копіюйте `EUSignCP.dll` до каталогу DPS XML Recovery. Програма використовує бібліотеку з офіційної локальної інсталяції.

Опис авторизації та XML endpoint оприлюднений у [документації приватного API Електронного кабінету](https://cabinet.tax.gov.ua/help/en/api-registers-int.html).

## Швидкий старт

1. Завантажте ZIP із GitHub Releases.
2. За бажанням звірте SHA-256 ZIP із хешем у тексті релізу.
3. Повністю розпакуйте ZIP у звичайний каталог користувача. Не запускайте EXE безпосередньо з архіву.
4. Запустіть `DPSXmlRecovery.exe`.
5. Натисніть **«Перевірити ІІТ»**. Продовжуйте лише після успішної перевірки.
6. Введіть власний ЄДРПОУ або РНОКПП.
7. Виберіть локальний JKS-файл, натисніть оновлення alias і виберіть потрібний alias.
8. Введіть пароль КЕП. Пароль потрібен лише поточному worker-процесу й не зберігається.
9. Виберіть початковий і кінцевий роки відновлення.
10. Виберіть окремий каталог для нового архіву. Не використовуйте каталог із єдиною резервною копією.
11. Виберіть режим і натисніть **«Почати відновлення»**.
12. Дочекайтеся фінального аудиту. Успішним повне відновлення є лише тоді, коли інтерфейс показав **PASS** після завершення аудиту.

## Зупинка та продовження

Кнопка **«Зупинити»** надсилає worker-процесу запит на кооперативну зупинку. Завершення відбувається на найближчій безпечній контрольній точці, тому може бути не миттєвим.

Щоб продовжити, знову запустіть програму, виберіть той самий каталог, період і режим, повторно введіть пароль КЕП та запустіть завдання. Вже перевірені об’єкти не завантажуються повторно. Не видаляйте і не редагуйте `data`, manifest або state між зупинкою та продовженням.

## Режими

### Повне відновлення

Виконує перевірку API, повний inventory, завантаження основних і пов’язаних XML, побудову manifest та фінальний аудит. PASS з’являється тільки після успішного аудиту.

### Тільки inventory

Отримує перелік доступних документів і перевіряє повноту сторінок, але не завантажує XML. Успішне завершення inventory не є фінальним PASS архіву.

### Тільки аудит

Працює локально з уже наявним архівом, не потребує JKS і не звертається до ДПС. Перевіряє state, manifest, XML, SHA-256, помилки та залишкові `.part`-файли.

Технічні режими приховані в розділі додаткових налаштувань і не потрібні для звичайного відновлення.

Для контрольного CLI типовим коренем є відносний каталог `recovery` у поточному робочому каталозі. Його можна змінити параметром `--root` або змінною `DPS_XML_RECOVERY_ROOT`. Якщо оператор має окремий незмінний контрольний архів, його шлях можна заборонити для CLI через `DPS_XML_RECOVERY_LEGACY_ROOT`; список захищених коренів GUI задається через `DPS_XML_RECOVERY_PROTECTED_ROOTS`, розділений системним роздільником шляхів.

## Де зберігаються дані

- каталог, вибраний користувачем: XML, metadata, state, manifest та audit report;
- `portable-data` поруч із EXE або в явно вибраному доступному каталозі: налаштування та безпечні operational logs;
- JKS залишається за вихідним шляхом і до дистрибутива не копіюється;
- пароль КЕП, Authorization і вміст XML не записуються в налаштування або діагностичні журнали.

Шлях до JKS запам’ятовується лише після явного ввімкнення відповідної опції. Для публікації завжди використовується порожній `portable-data`.

## Типові проблеми

- **«ІІТ не готовий»** — перевірте офіційну інсталяцію, x86 DLL, її цифровий підпис і налаштування сертифікатів. Не завантажуйте DLL із неофіційних джерел.
- **JKS або alias не читається** — перевірте файл, права доступу, alias і пароль. Програма не відновлює пароль і не змінює JKS.
- **Помилка авторизації** — перевірте чинність КЕП, право підпису, системний час і налаштування ІІТ. Не надсилайте стороннім JKS, пароль або повний Authorization.
- **Inventory або API не завершується** — перевірте мережу й доступність Електронного кабінету, повторіть пізніше та експортуйте безпечну діагностику. Частковий inventory не є повним архівом.
- **Залишилися `.part` або аудит failed** — PASS не підтверджено. Не редагуйте `.part`; повторіть запуск із тим самим каталогом або audit-only.
- **SmartScreen** — EXE не підписаний. Перевірте джерело ZIP і SHA-256; якщо походження не підтверджене, не запускайте файл.

## Безпека і приватність

- ключ і пароль КЕП не передаються розробнику;
- пароль передається локальному worker-процесу одноразовим Windows anonymous pipe, а не через argv, environment, файл або JSONL;
- `EUSignCP.dll` не входить до ZIP і використовується з установленого користувачем офіційного комплексу ІІТ;
- локальна внутрішня підписана авторизація використовується для взаємодії з приватним API ДПС;
- програма фільтрує operational logs і діагностику, але це не є заявою про абсолютну безпеку;
- користувач відповідає за захист JKS, каталогу архіву, Windows-облікового запису та резервних копій.

Перед передаванням діагностичного звіту перевірте його самостійно. Не публікуйте XML, JKS, пароль, Authorization, персональні дані або каталоги відновлення.

## Перевірений результат

Для кандидата 2.0.2 автоматизовано пройдено 177 тестів і package audit. Користувач окремо підтвердив реальне відновлення 347 XML: 135 основних, 212 пов’язаних, 0 невалідних XML, 0 `.part`, 0 помилок аудиту, фінальний аудит PASS.

Цей результат підтверджує конкретний перевірений запуск, але не гарантує однаковий результат для кожного облікового запису, ключа, мережі або майбутньої версії API.
